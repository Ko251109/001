# inbox-draft — 気付きメモからブログ下書きを作る

`00_inbox/` の気付きメモを材料に、**1トピックを深掘り**するブログ記事を **yaque文体** で作る。
索引→期間で絞ってメモを読む→トピック選定→文体適用→ドラフト提示→承認後に保存、の順で進める。

## 手順

### 1. 索引を読む
- まず `WIKI.md` を読み、このジャンルのルート（トピックまとめ）を確認する。

### 2. 期間と範囲を決める
- ユーザー指定の期間（例「一週間以内」「今月」）を確認。指定が無ければ**直近7日**を既定とする。
- 対象は `00_inbox/`。各メモの日付は次の順で判定する:
  1. ファイル名先頭の `YYYY-MM-DD`
  2. frontmatter の `date:`
  3. ファイルの更新日時（mtime）
- 該当期間のメモ一覧を作る（`00_inbox/README.md` も参照）。

### 3. メモを読み、トピックを選ぶ
- 対象メモを読み、繰り返し出てくる関心・引っかかり・問いを拾う。
- **1記事＝1トピック**。最も書き応えのある（複数メモにまたがる／問いが立っている）テーマを1つ選ぶ。
- どれを選ぶか迷う場合は候補を2〜3個提示して確認する。

### 4. 文体ファイルを読む（必要な分だけ）
- `04_テンプレート/トピックまとめテンプレート.md`（構成・このジャンルの文体注意）… 必読
- `CLAUDE.md`（文末・一人称・感情・締めのトーン規則）… 必読
- 言い回しに迷えば `03_表現辞典/頻出表現辞典.md`

### 5. ドラフトを書く
- テンプレの構成（静かな書き出し→背景→観察と気付きの展開→揺らぎ→あっさり締め）。
- yaque文体のトーン規則を厳守（主語省略・感情は描写で・感嘆符やネットスラング禁止・締めはあっさり）。
- **ライブレポート固有の書き出し**（「〇〇のライブに行ってきました。」）や演奏描写の語彙は使わない。
- メモに書かれた事実だけを使う。膨らませたい点があれば**捏造せず筆者に確認**する。

### 6. 提示する（保存しない）
- ドラフトを全文提示し、トピック選定が合っているか・修正点を尋ねる。
- フィードバックを反映して再提示する。

### 7. 承認後に保存（WIKI.md §4 の自己メンテナンス）
- 保存先: `01_記事アーカイブ/音楽の話/` ではなく、エッセイ系は `01_記事アーカイブ/その他/` に置く。
  （新カテゴリを設けたい場合は WIKI.md と INDEX.md を更新してから）
- ファイル名: `YYYY-MM-DD_気付きの話(短いトピック名).md`（日付は執筆日 or 対象期間の代表日）。
- frontmatter（title / date / tags）を付ける。
- 保存したら `01_記事アーカイブ/INDEX.md` の本数（§1）を同期する。
- フィードバックから抽象化した学びが得られたら `WIKI.md §4.1` に従い反映する。

## 使い方の例

```
/inbox-draft 一週間以内の気付きメモから1本ブログにして
/inbox-draft 今月のメモで一番引っかかってるテーマを深掘りして
```
