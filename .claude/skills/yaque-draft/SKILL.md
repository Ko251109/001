# yaque-draft — ブログ下書き生成スキル

お題を受け取り、このVault（LLM Wiki）の文脈を使ってyaqueの文体でブログ記事のドラフトを作る。
**索引→必要なファイルだけ読む→手本を数本だけ引く→文体適用→ドラフト提示→承認後に保存**の順で進める。
全ファイルや209本の記事を全文読み込まないこと。

## 手順

### 1. 索引を読む
- まず `WIKI.md` を読み、§1 タスク別ルーティングで読むべきファイルを特定する。

### 2. お題を整理する
ユーザーの入力から以下を抽出する。足りない必須情報があれば**捏造せず質問する**。
- アーティスト名／会場／**公演日**（保存時のファイル名に必須）
- 記事種別（ライブ / フェス / 年間ベスト）→ テンプレートA/B/Cを選ぶ
- セットリスト・演出・MC・席・印象などのメモ

### 3. 文脈ファイルを読む（必要な分だけ）
- `CLAUDE.md`（文体の核心ルール）… 必読
- `04_テンプレート/ライブレポートテンプレート.md`（骨組み・チェックリスト）
- `03_表現辞典/頻出表現辞典.md`（言い回しに迷ったとき）
- 推敲フェーズでは `00_エージェント設定/文章改善ポイントレポート.md`

### 4. 手本を引く（全部読まない）
- `01_記事アーカイブ/INDEX.md` を見て、**同じアーティスト**または**同じ会場**の過去記事を
  ファイル名検索（Glob/Grep）で特定し、**1〜2本だけ**精読する。
- 該当が無ければ INDEX.md の「推奨手本（最新の洗練された文体）」を1本読む。
- 前例から固有モチーフ（その会場特有の演出など）を拾い、今回と差別化する。

### 5. ドラフトを書く（CLAUDE.md を厳守）
- 書き出しは「〇〇のライブに行ってきました。」系＋2文目で文脈補足。
- 主語（私は/僕は）を省略。曲名は「」。感嘆符・「ヤバい」「神」「最高すぎる」は使わない。
- 感情は直接語らず描写で伝える。曲名の羅列は動詞を変えて単調を避ける。
- 締めは3軸（体験／過去公演との相違／固有要素）を**全部入れず、あっさり短く**まとめる。
- 詳細は `CLAUDE.md` の各ルールに従う。

### 6. 提示する（この時点では保存しない）
- ドラフトを全文提示し、修正点を尋ねる。
- フィードバックがあれば反映して再提示する。

### 7. 承認後に保存（WIKI.md §4 の自己メンテナンス）
- 保存先: `01_記事アーカイブ/<種別フォルダ>/`
- ファイル名規則: `YYYY-MM-DD_ライブの話(アーティスト 日付 会場).md`
  （プレフィックスは公演日。日付不明なら保存しない／確認する）
- frontmatter（title / date / categories / tags）を既存記事に合わせて付ける。
- 保存したら `01_記事アーカイブ/INDEX.md` の本数（§1）と頻出アーティスト表（§3）を同期する。
- フィードバックから**抽象化した学び**が得られたら、`WIKI.md §4.1` の表に従い適切なファイル
  （文体ルール=`CLAUDE.md`、言い回し=`03_表現辞典/` 等）に反映する。

## 使い方の例

```
/yaque-draft TOMOO 6/20 日本武道館。新譜ツアーのファイナル。
オープニングは「高台」、アンコールで新曲。席は2階後方。
```

→ 索引→手本検索→文体適用でドラフトを提示。修正を受けて保存まで行う。
